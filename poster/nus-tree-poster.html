NUS-TREE

By: Arav Cabral & Raghuveer Singh

A visual dependency mapper for NUS modules. The current build connects to live NUSMods data, builds a prerequisite tree, and keeps the graph editable for planning.

The Problem

Planning modules across multiple years is hard because students need the full prerequisite chain, not just the one line of prerequisite text shown for a single course. A student aiming for a higher-level module may only realise later that a Year 1 or Year 2 foundation module was needed. That mistake can affect exchange plans, specialisations, or graduation timing.

Current Solution

NUS-Tree turns module planning into a graph. A student enters a module code, our Next.js API route fetches the matching NUSMods record, and My Tree expands the prerequisite modules it finds. The student can then inspect the dependency path visually instead of checking modules one by one.

What is actually working right now

The prototype now uses real module data. It reads the selected target module, calls the backend route, normalizes the NUSMods response, extracts module codes from the prerequisite text, and recursively visits those modules until the graph is built.

Built So Far

Live NUSMods lookup is integrated on the home page and in My Tree. The backend chooses the academic year from the current date and returns a clean object with the module code, title, description, prerequisite text, and semester availability. The frontend uses React Flow so the generated graph remains interactive instead of being a static image.

What changed

  • My Tree is no longer hardcoded: the graph is generated from the selected module code.
  • Home page lookup works: users can load real NUSMods module details before exploring.
  • Errors are handled: missing or invalid module codes return friendly messages instead of crashing.
  • Canvas tools remain: editing, notes, manual links, and layout helpers still work with generated nodes.

Testing + CI

  • API tests: check NUSMods response normalization, invalid modules, and missing module codes.
  • Academic year: tests cover both the dynamic default year and explicit year override.
  • Browser tests: Playwright smoke tests confirm the main pages and navigation still load.
  • CI workflow: GitHub Actions runs install, unit tests, build, and browser checks.

Known limits + next

  • Logic parser: distinguish AND requirements from OR alternatives instead of flattening them.
  • Multiple goals: combine several Level 3000/4000 targets into one planning tree.
  • NUSMods import: import a plan and validate prerequisites by semester order.
  • Unlocks View: show what future modules become available after taking a module.

Why this already helps

The current prototype answers the first planning question: "What do I need before this module?" Instead of manually opening several NUSMods pages, students can generate a visual starting point, inspect the prerequisites, and then adjust the graph with notes or manual edits for their own plan.

Next build target

The biggest remaining gap is prerequisite meaning. Some NUSMods text says "take all of these"; other text says "take one of these". The next version should preserve that distinction visually, then support multi-target trees and NUSMods plan import.
